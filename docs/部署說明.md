# 部署到 Cloudflare Pages

專案已經設定好，部署時只需要在 Cloudflare 的網頁介面點選即可，不必輸入任何指令。

> **這個階段完全不會動到正式網域 `novananoinks.com.tw`。**
> 舊站照常運作，你會拿到一個 `xxx.pages.dev` 的測試網址供驗收。

---

## 一、建立專案（約 5 分鐘）

1. 到 <https://dash.cloudflare.com/> 註冊或登入（免費方案即可）
2. 左側選單 → **Workers & Pages** → **Create** → 切到 **Pages** 分頁
   → **Connect to Git**
3. 授權 GitHub，選擇儲存庫 `novachemclaudecowork-a11y/novapage`
4. 設定頁面填入：

   | 欄位 | 填什麼 |
   |---|---|
   | Project name | `novananoinks`（會成為網址 `novananoinks.pages.dev`） |
   | Production branch | `claude/website-clone-assessment-x09jd5` |
   | Framework preset | **Astro** |
   | Build command | `npm run build` |
   | Build output directory | `dist` |

5. 按 **Save and Deploy**

第一次建置約 1～2 分鐘。完成後會給你測試網址。

### 如果建置失敗說 Node 版本不對

錯誤訊息長這樣：

```
Node.js v20.x.x is not supported by Astro!
Please upgrade Node.js to a supported version: ">=22.12.0"
```

專案根目錄的 `.nvmrc` 已指定 `22`，Cloudflare 會據此安裝 Node 22。
若仍抓到舊版本，多半是建置快取或建置映像檔版本的問題，依序試：

1. **Deployments → 最新那筆 → Retry deployment**（清掉快取重跑）
2. **Settings → Build → Build system version** 改為 **v2** 後重新部署
3. 仍不行的話，到 **Settings → Environment variables** 新增
   `NODE_VERSION` = `22`，再重新部署

本機可以先自己驗證版本設定是否一致：

```bash
npm run check:node
```

## 二、環境變數

### 驗收階段：**不要設定任何環境變數**

專案預設會輸出「禁止搜尋引擎索引」的 `robots.txt`：

```
User-agent: *
Disallow: /
```

**這是刻意的。** 測試站若被 Google 收錄，會與仍在線上的舊站形成重複內容，
兩邊的搜尋排名都會受影響。

### 正式上線時才加這兩項

到專案的 **Settings → Environment variables → Production** 新增：

| 變數名稱 | 值 |
|---|---|
| `SITE_ENV` | `production` |
| `SITE_URL` | `https://www.novananoinks.com.tw` |

加完後重新部署一次（Deployments → 最新那筆 → Retry deployment）。
此時 `robots.txt` 會改為開放索引並附上 sitemap。

## 三之二、Pages 專案還是 Workers 專案？

Cloudflare 有兩種部署靜態網站的方式，**轉址的接法不一樣**，請先確認你是哪一種：

| 看網址 | 類型 | 轉址由誰處理 |
|---|---|---|
| `xxx.pages.dev` | Pages 專案 | `functions/_middleware.js`（Cloudflare 自動載入） |
| `xxx.workers.dev` | Workers 專案 | `worker/index.js` + `wrangler.jsonc`（需額外設定） |

⚠️ **`functions/` 是 Pages 專屬的慣例，Workers 專案不會載入它。**
若你拿到的是 `.workers.dev` 網址，轉址預設是**沒有生效**的，需要補上設定。

### 怎麼驗證轉址有沒有生效

在瀏覽器打開（把網域換成你的）：

```
https://你的網址/view.html?id=127&pd_type=1&m=1&pg=6
```

- **有跳到** `/products/cw-waterbased/`（CW水性油墨）→ 轉址正常
- **顯示 404 或停在原網址** → 轉址沒生效

### Workers 專案的設定

`wrangler.jsonc` 已在專案根目錄，由 `worker/index.js` 先處理轉址，
其餘請求再交給 `dist/` 的靜態檔案。

其中 `name` 必須與 Workers 專案名稱一致（即網址 `名稱.帳號.workers.dev` 的第一段）。
目前設為 `novapage`，若專案名稱不同請一併修改。

> ⚠️ 若建置時出現 assets 設定衝突的錯誤，檢查 Cloudflare 專案的
> **Settings → Build → Deploy command** 有沒有帶 `--assets=dist` 這類參數。
> 設定檔裡已經指定 assets，指令上不能重複指定，把那段參數拿掉即可。

### 部署後怎麼確認 Worker 真的在跑

打開：

```
https://你的網址/__worker-check
```

- 顯示 `ok` → Worker 有在執行，轉址若仍不對就是邏輯問題
- 顯示 404 頁面 → 部署的版本沒帶到 Worker，要回頭看建置設定
  （`wrangler.jsonc` 是否在根目錄、Deploy command 是否為 `npx wrangler deploy`）

> ⚠️ `wrangler.jsonc` 裡的 `run_worker_first: true` 不能拿掉。
> 預設是先比對靜態資源、比不到才交給 Worker；但只要設了
> `not_found_handling`，資源路由器就會自己回應找不到的請求，
> **Worker 永遠不會被呼叫**，舊網址轉址會全部失效。
> 這個差異在本機 `wrangler dev` 上看不出來，只有部署後才會顯現。

### 本機驗證

專案已含 wrangler，可在本機用真正的 Workers 執行環境跑起來：

```bash
npm run build
npx wrangler dev --local
```

另開一個終端機測轉址：

```bash
curl -s -o /dev/null -w "%{redirect_url}\n" \
  "http://127.0.0.1:8787/view.html?id=127&pd_type=1&m=1&pg=6"
```

應輸出 `http://127.0.0.1:8787/products/cw-waterbased/`。

`worker/index.js` 已經在專案裡了，它與 Pages 用的 `functions/_middleware.js`
共用 `src/lib/legacy-redirects.mjs` 的判斷邏輯，兩邊行為完全一致。

## 四、轉址是怎麼做的

⚠️ 這裡有個容易踩的坑：**Cloudflare Pages 的 `_redirects` 檔只比對路徑，不比對查詢字串。**

舊站的產品網址形如 `/view.html?id=127&m=1&pg=6`，路徑部分只有 `/view.html`，
所以逐筆列出完整舊網址在 Cloudflare 上**一筆都不會生效**。

因此轉址改在程式裡讀取查詢參數後再導向。判斷邏輯集中在
`src/lib/legacy-redirects.mjs`（由 `scripts/build_redirects.py` 自動產生），
兩個平台各有一層很薄的轉接：

| 檔案 | 用於 |
|---|---|
| `src/lib/legacy-redirects.mjs` | 共用的對照表與判斷邏輯（自動產生，勿手改） |
| `functions/_middleware.js` | Cloudflare **Pages** 專案 |
| `worker/index.js` | Cloudflare **Workers** 專案 |

驗證方式：

```bash
npm run build && npm test
```

`npm test` 會做兩件事：

1. **Node 版本一致性檢查**（`scripts/check_node.mjs`）——
   確認 `.nvmrc`、`package.json` 的 `engines` 與 Astro 實際要求的版本沒有互相矛盾。
   加這項是因為曾經 `.nvmrc` 寫 20 而 Astro 要求 22，本機剛好是 22 所以沒發現，
   直到 Cloudflare 依 `.nvmrc` 裝了 Node 20 才建置失敗。
2. **轉址驗證**——取鏡像中實際存在的 **160 個舊網址**逐一驗證，確認：
1. 每個舊網址都能解析出新網址
2. 目標頁面確實存在
3. **導到的產品就是舊站原本顯示的那一項**（不是只要有頁面就算過）

目前 160 筆全數通過。

## 五、正式上線切換（驗收通過後才做）

> 詳細的前置準備見 [`接管檢查清單.md`](接管檢查清單.md)。

1. **先確認 DNS 管理權已在公司手上**（見接管檢查清單第二節）
2. 在 Cloudflare Pages 專案 → **Custom domains** → 加入
   `www.novananoinks.com.tw` 與 `novananoinks.com.tw`
3. 依畫面指示設定 DNS 記錄
   - ⚠️ **MX 記錄務必原封不動保留**，否則公司信箱會收不到信
4. 設定第二節的兩個環境變數並重新部署
5. 到 Google Search Console 提交新的 sitemap：
   `https://www.novananoinks.com.tw/sitemap-index.xml`
6. **舊站先別關**，保留一至三個月作為備援與對照
