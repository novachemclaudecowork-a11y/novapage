# 開發說明

## 環境需求

- Node.js 20 以上
- Python 3.11 以上（只有重新產生資料時才需要）

## 常用指令

```bash
npm install          # 安裝相依套件
npm run dev          # 本機開發，預設 http://localhost:4321
npm run build        # 編譯靜態檔到 dist/
npm run preview      # 預覽編譯結果
npm run rebuild      # 重新產生資料後再編譯（= npm run data && npm run build）
```

## 資料從哪裡來

新站的所有產品資料，都是從 `site-mirror/`（舊站的完整鏡像）自動萃取出來的，
不是手動輸入的。流程如下：

```
site-mirror/            舊站鏡像（唯讀，不要手動修改）
    ↓  scripts/extract_products.py
src/data/products.json  萃取出的 40 項產品
    ↓  scripts/build_catalog.py
src/data/catalog.json   ← 網站實際讀取的資料
src/data/redirects.json 舊網址 → 新網址對照
    ↓  scripts/prepare_assets.py
public/images/          產品照與 Logo
src/data/pages.json     公司簡介等靜態頁文字
    ↓  scripts/build_redirects.py
public/_redirects       部署平台用的 301 轉址設定
```

一次跑完整條管線：

```bash
npm run data
```

### ⚠️ 萃取程式的關鍵前提

舊站（H3 B2B System）網址中的 `id` 參數**會被伺服器忽略**，
實際顯示哪一項產品是由「分類 `m` + 分頁序號 `pg`」決定。
因此 `extract_products.py` 以 `(m, m2, pg)` 作為產品的唯一鍵。

**修改萃取邏輯時請勿改回用 `id`**，否則會把不同產品誤判為重複。
詳細說明見 [`鏡像分析報告.md`](鏡像分析報告.md) 第四節。

## 要改內容的話

| 想改什麼 | 改哪裡 |
|---|---|
| 公司名稱、電話、地址 | `src/data/site.ts` 的 `company` |
| 主選單項目 | `src/data/site.ts` 的 `mainNav` |
| 產品網址代稱（英文 slug） | `scripts/build_catalog.py` 的 `SLUGS`，改完跑 `npm run data` |
| 產品名稱錯字 | `scripts/build_catalog.py` 的 `NAME_CORRECTIONS` |
| 配色、字體、版面 | `src/styles/global.css` |
| 頁面版型 | `src/layouts/BaseLayout.astro`、`src/components/` |

> 產品的名稱與說明目前來自鏡像，屬於自動產生的資料。
> 日後若要讓非技術同仁自行上稿，可再接上輕量後台（如 Sveltia CMS），
> 一樣免費且不需要伺服器。

## 詢價清單怎麼運作

靜態網站沒有後端，所以詢價清單存在**瀏覽器的 localStorage**
（`src/scripts/inquiry.ts`），送出時組成郵件內容開啟使用者的郵件軟體。

好處是零成本、零維運、不會有資料外洩風險。
若日後希望詢價單直接進到信箱而不經過使用者的郵件軟體，
可改接表單服務（Formspree、Cloudflare Workers 等），只需改 `inquiry.astro` 的送出邏輯。
