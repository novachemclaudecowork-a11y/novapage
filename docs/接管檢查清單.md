> 這幾項與技術無關，是管理層該確認的事。

## 一、網域所有權 ✅ 已確認安全

網域 `novananoinks.com.tw` 由貝星貿易自行註冊 —— **這是最關鍵的一項，而且已經在手上。**

這代表貴公司握有對這個網域的**最終決定權**。後面所有事情都好辦。

### 仍建議做的兩件事（10 分鐘）

1. **確認登記資料仍然正確**
   到 <https://whois.twnic.net.tw/> 輸入 `novananoinks.com.tw`，確認：
   - [ ] Registrant（註冊人）仍是貝星貿易，未被變更過
   - [ ] 到期日還有多久，續約是誰在付款
   - [ ] Registrar（受理註冊機構）是哪一家 —— **請記下來，下一步會用到**

2. **確認公司握有註冊商後台的帳號密碼**
   - [ ] 找出當初註冊時使用的帳號與密碼（可能在財務或早期承辦人手上）
   - [ ] 登入試試看能不能進得去
   - [ ] 若密碼遺失，憑公司登記文件向註冊商申請重設 —— 因為註冊人是公司，這一定辦得到

## 二、DNS 管理權 ⚠️ 唯一待處理項目（但可單方面解決）

### 關鍵觀念（請務必理解這一點）

DNS 有兩層，很多人會搞混：

```
第一層：網域註冊商（Registrar）  ← 貴公司握有 ✅
          ↓ 在這裡設定「要用誰家的 Name Server」
第二層：Name Server（DNS 代管）  ← 目前可能在設計公司手上 ⚠️
          ↓ 實際存放 A / MX / CNAME 等紀錄
```

**因為貴公司控制第一層，所以可以隨時把第二層換掉，不需要設計公司同意。**

這就是為什麼「網域自己註冊」如此重要 —— 它讓你永遠保有退路。

### 怎麼確認現況

登入網域註冊商的管理後台，找「**名稱伺服器**／**Name Server**／**DNS 設定**」：

- 如果顯示的是註冊商自己的（例如 `dns1.hinet.net`）→ DNS 在貴公司這邊，完全沒問題
- 如果顯示的是陌生的網址（例如 `ns1.某設計公司.com.tw`）→ DNS 目前由設計公司代管

### 建議做法：把 DNS 移到 Cloudflare（免費、一勞永逸）

**⚠️ 執行順序很重要，做反了會導致網站斷線或信件遺失：**

1. **先完整記錄現有的 DNS 紀錄**（這一步絕對不能跳過）
   - 到 <https://mxtoolbox.com/SuperTool.aspx> 逐一查詢 `novananoinks.com.tw` 的
     **A**、**MX**、**TXT**、**CNAME** 紀錄，全部截圖存檔
   - 或請我協助整理成清單

2. **在 Cloudflare 註冊免費帳號**，加入 `novananoinks.com.tw`
   - Cloudflare 會自動掃描並匯入現有紀錄 —— 但**務必人工比對第 1 步的清單**，
     自動掃描可能會漏掉紀錄

3. **確認所有紀錄都正確搬過去之後**，才到註冊商後台把 Name Server 改成 Cloudflare 給的兩組網址

4. 等待生效（通常數分鐘到 24 小時）

完成後：**DNS 管理權 100% 回到公司手上，與任何廠商脫鉤，且往後免費。**

> 💡 這件事可以**現在就做**，不必等新網站完成。
> 只要紀錄搬得完整，網站與信件都不會受影響，使用者完全無感。
> 提前做好，將來新站要上線時就只是改一筆 A 紀錄的事。

## 三、企業信箱 ✅ 已確認安全

`novachem@ms24.hinet.net` 是中華電信 HiNet 的信箱，且**早在找設計公司之前就在使用**。

代表：
- ✅ 信箱與網站主機**完全無關**，換網站不會斷信
- ✅ 也與設計公司無關，對方碰不到

### 仍需確認一項

- [ ] 公司有沒有另外使用 `@novananoinks.com.tw` 結尾的信箱？
  （例如 `sales@novananoinks.com.tw`）

若**沒有** → 這一項完全不必操心，搬 DNS 時也不用擔心 MX 紀錄。
若**有** → 搬 DNS 時 **MX 紀錄必須原封不動保留**，否則信件會全部收不到。

## 四、既有資產盤點（建議補做）

- [ ] **原始合約**：調閱與設計公司的合約，確認服務範圍、終止條件、年費項目
- [ ] **付款紀錄**：每年付給對方的費用中，哪些是主機費、哪些是維護費
      （網域費應該是公司自己繳給註冊商，可以核對確認）
- [ ] **Google Search Console** 的網站擁有權在誰手上？
- [ ] **Google Analytics** 帳號在誰手上？（換站後需延續流量數據）
- [ ] **Google 商家檔案**（Google Business Profile）誰在管理？
- [ ] **SSL 憑證**：目前由誰申請續約？
      （新站用 Cloudflare / Vercel 會自動免費簽發，此項可直接淘汰，不再需要付費）
- [ ] **產品素材原檔**：產品照高解析原檔、型錄 PDF、規格書，公司內部有無留底？
      網站上的是壓縮版，有原檔重建品質會更好

## 五、切換上線時的注意事項

等新站做好、準備切換時：

1. **先在測試網址上完整驗收**（Cloudflare Pages 會提供免費預覽網址），不要直接動正式網域
2. **保留舊網址的轉址對照**
   舊站的 `view.asp?id=132&...` 這類網址 Google 已經收錄，
   新站須設定 **301 轉址**指向對應新網址，否則搜尋排名會掉。
   （重建時我會一併產出這份對照表）
3. **切換前再次確認 MX 紀錄無誤**，避免信箱中斷
4. **舊站先別急著關**，保留一至三個月作為備援與對照
5. 切換後到 Google Search Console 提交新的 sitemap

## 六、與設計公司的溝通建議

因為網域在貴公司手上，**談判地位其實很好**，不需要急，也不必起衝突。

建議**不要**一開始就談「交出原始碼」—— 依台灣《著作權法》第 12 條，
出資聘人完成的著作若未特別約定，著作權原則上歸受聘人，
這個要求容易陷入僵局，而且那些老舊的 ASP 程式碼**拿到也沒有用**。

比較有效的談法是就事論事：

> 「我們要進行公司網路資產的盤點，請提供目前 `novananoinks.com.tw` 的
>  完整 DNS 紀錄清單（A、MX、CNAME、TXT），以及網站上所使用的
>  產品照片原始檔。」

這是正當、具體的資產管理要求。

而且 —— 就算對方完全不配合也沒關係。DNS 紀錄可以自己用工具查出來，
產品照可以從網站上直接下載。**貴公司不需要對方的任何配合就能完成搬遷。**
